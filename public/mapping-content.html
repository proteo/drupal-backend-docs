Mapping content ​

Turn a Drupal content model into descriptor entries. Each entry names a Drupal bundle, the fields and relations to read, and the routes to serve. This page maps one content type end to end and contrasts two models.

Before you start ​

  • A working Quick start or an installed package.
  • The Drupal content type exists and anonymous users can read it. See Backend setup.
  • Know the role of each type: primary, facet, page or reference.

What one entry produces ​

An entry under content_types decides the routes, the fetcher call and the views. The diagram follows the talk entry of the example.

The routes and view names are covered in Routes and controllers and Views and overrides.

1. Find the bundle and its fields ​

Open the collection in a browser to see the names Drupal uses:

text
https://drupal.example/jsonapi/node/talk

Check: the response has data items with attributes such as title and short_description, and relationships such as speaker. The resource type node--talk gives entity_type node and bundle talk.

2. Declare the type and its fields ​

Start with identity and fields. A field reads one attribute under a name of your choice:

php
'talk' => [
    'entity_type' => 'node',
    'bundle' => 'talk',
    'url_prefix' => 'talk',
    'alias_prefix' => '',
    'listing_path' => '/talks',
    'per_page' => 15,
    'default_sort' => '-created',
    'decorator' => TalkDecorator::class,
    'fields' => [
        'title' => ['source' => 'title', 'required' => true],
        'date' => ['source' => 'created', 'type' => 'date'],
        'teaser' => ['source' => 'short_description', 'type' => 'html'],
        'content' => ['source' => 'description', 'type' => 'html'],
        'review_id' => ['source' => 'review_reference'],
    ],
    'relations' => [
        'speakers' => ['to' => 'speaker', 'via' => 'speaker', 'many' => true],
        'topics' => ['to' => 'topic', 'via' => 'topic', 'many' => true],
        'tracks' => ['to' => 'track', 'via' => 'tracks', 'many' => true],
        'slide_resources' => ['to' => 'resource', 'via' => 'slides_resources', 'many' => true],
        'recording_resources' => ['to' => 'resource', 'via' => 'recording_resources', 'many' => true],
        'deck' => ['to' => 'slides', 'via' => 'deck', 'optional' => true],
        'cover' => ['type' => 'image', 'via' => 'cover', 'image_field' => 'field_media_image'],
    ],
    'includes' => [
        'item' => ['speakers', 'topics', 'tracks', 'slide_resources', 'recording_resources', 'cover'],
        'listing' => ['cover', 'speakers', 'topics', 'slide_resources', 'recording_resources'],
    ],
    'filters' => [
        'topic' => ['type' => 'equals', 'relation' => 'topics', 'native_path' => 'topic.id'],
        'speaker' => ['type' => 'equals', 'relation' => 'speakers', 'native_path' => 'speaker.id'],
        'track' => ['type' => 'equals', 'relation' => 'tracks', 'native_path' => 'tracks.id'],
        'year' => ['type' => 'year_range', 'native_path' => 'created', 'first_year' => 2021],
        'materials' => ['type' => 'boolean', 'fields' => ['slides' => ['native' => 'has_slides'], 'recording' => ['native' => 'has_recording']], 'match' => 'any'],
    ],
    'sorts' => ['newest' => '-created', 'oldest' => 'created', 'title' => 'title'],
    'suggest_subtitle' => 'speakers',
    'term_fields' => ['title' => 5, 'description.value' => 1],
    'related_term_fields' => ['speaker.title' => 3, 'topic.name' => 2, 'tracks.name' => 2],
    'seo' => ['title' => 'title', 'description' => ['field' => 'teaser', 'max' => 160], 'image' => 'cover', 'author' => 'speakers'],
],
  • title is required: if Drupal omits it, the page is a bad response instead of rendering empty.
  • teaser has the type html, so links and file paths in it point to your frontend and to Drupal's files.
  • date has the type date, a string from Drupal's ISO 8601 value.

The options of each key are in the Descriptor reference.

3. Add relations ​

A relation follows a JSON:API relationship. Its via is the relationship name in Drupal, and its type decides what your view receives:

TypePoints atView receives
contentAnother content type, named by toAn Entity, or a list of them with many
fileA file entity, or a media type's source fieldA File with url, name, mime and size
imageA media entity with a fileAn Image with src, alt and image styles

List the relations to load in includes. item is used by the item page and listing by listings and search rows. Load only what the view shows, because each include enlarges the JSON:API response.

Check: php artisan drupal:contract shows each relationship with its include path, and php artisan drupal:validate confirms Drupal has them.

4. Set the routes ​

Three options decide the URLs of a primary or facet type:

OptionTalk exampleResult
url_prefixtalkThe item page is /talk/{alias}.
alias_prefix''The Drupal alias is /{alias}, with no prefix.
listing_path/talksThe listing is /talks, named talk.index.

The two prefixes are independent. The URL prefix is what visitors see; the alias prefix is what Drupal stores. Without either, both default to the content type key.

Contrast: a different model ​

The article fixture maps a Drupal site with different habits. Here the Drupal alias already contains the prefix (/articles/my-story), so both prefixes are articles, and some relations are optional:

php
'article' => [
    'role' => 'primary',
    'entity_type' => 'node',
    'bundle' => 'article',
    'url_prefix' => 'articles',
    'alias_prefix' => 'articles',
    'listing_path' => '/articles',
    'fields' => [
        'title' => ['source' => 'title', 'required' => true],
        'published' => ['source' => 'created', 'type' => 'date'],
        'body' => ['source' => 'body', 'type' => 'html'],
    ],
    'relations' => [
        'writers' => ['to' => 'writer', 'via' => 'uid_writer', 'many' => true],
        'topics' => ['to' => 'topic', 'via' => 'field_topic', 'many' => true, 'optional' => true],
        'genre' => ['to' => 'genre', 'via' => 'field_genre'],
        'hero' => ['type' => 'image', 'via' => 'field_hero', 'image_field' => 'field_media_image', 'optional' => true],
    ],
    'includes' => [
        'item' => ['writers', 'topics', 'genre', 'hero'],
        'listing' => ['hero', 'genre'],
    ],
    'filters' => [
        'topic' => ['type' => 'equals', 'relation' => 'topics', 'native_path' => 'topics.id'],
        'genre' => ['type' => 'equals', 'relation' => 'genre', 'native_path' => 'genre.id'],
    ],
    'sorts' => ['newest' => '-created'],
],
AspectTalk exampleArticle example
Alias in Drupal/dune/articles/my-story
Item URL/talk/dune/articles/my-story
Image relationcover, requiredhero, optional: dropped and logged if it fails
Other typesspeaker (primary, not searchable), topic, track (facets)writer (primary, not searchable), topic, genre (facets); only writer and genre have listings
SearchEnabled with tabsNot configured

Neither model needs package code. The package reads your descriptor and nothing else.

Read the result in a view ​

A view receives the entity under the content type key and as $entity. Fields and relations have the names you chose:

blade
<h1>{{ $talk->title }}</h1>
{!! $talk->teaser !!}

An unknown name throws instead of returning empty, so a typo fails loudly in development. Every entity also has id, type, path and url().
