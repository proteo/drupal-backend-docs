Descriptor reference ​

Every option of a content type: content_types.<key> and the fields, relations, filters, conditions and SEO settings inside it. Settings outside the content types are in the Configuration reference.

Before you start ​

Know the terms content type, role, field and relation. Tables list the key relative to its table (conditions.*.attribute), its type, the default and the effect.

A complete content type, from the talk example:

php
'talk' => [
    'entity_type' => 'node',
    'bundle' => 'talk',
    'url_prefix' => 'talk',
    'alias_prefix' => '',
    'listing_path' => '/talks',
    'per_page' => 15,
    'default_sort' => '-created',
    'decorator' => TalkDecorator::class,
    'fields' => [
        'title' => ['source' => 'title', 'required' => true],
        'date' => ['source' => 'created', 'type' => 'date'],
        'teaser' => ['source' => 'short_description', 'type' => 'html'],
        'content' => ['source' => 'description', 'type' => 'html'],
        'review_id' => ['source' => 'review_reference'],
    ],
    'relations' => [
        'speakers' => ['to' => 'speaker', 'via' => 'speaker', 'many' => true],
        'topics' => ['to' => 'topic', 'via' => 'topic', 'many' => true],
        'tracks' => ['to' => 'track', 'via' => 'tracks', 'many' => true],
        'slide_resources' => ['to' => 'resource', 'via' => 'slides_resources', 'many' => true],
        'recording_resources' => ['to' => 'resource', 'via' => 'recording_resources', 'many' => true],
        'deck' => ['to' => 'slides', 'via' => 'deck', 'optional' => true],
        'cover' => ['type' => 'image', 'via' => 'cover', 'image_field' => 'field_media_image'],
    ],
    'includes' => [
        'item' => ['speakers', 'topics', 'tracks', 'slide_resources', 'recording_resources', 'cover'],
        'listing' => ['cover', 'speakers', 'topics', 'slide_resources', 'recording_resources'],
    ],
    'filters' => [
        'topic' => ['type' => 'equals', 'relation' => 'topics', 'native_path' => 'topic.id'],
        'speaker' => ['type' => 'equals', 'relation' => 'speakers', 'native_path' => 'speaker.id'],
        'track' => ['type' => 'equals', 'relation' => 'tracks', 'native_path' => 'tracks.id'],
        'year' => ['type' => 'year_range', 'native_path' => 'created', 'first_year' => 2021],
        'materials' => ['type' => 'boolean', 'fields' => ['slides' => ['native' => 'has_slides'], 'recording' => ['native' => 'has_recording']], 'match' => 'any'],
    ],
    'sorts' => ['newest' => '-created', 'oldest' => 'created', 'title' => 'title'],
    'suggest_subtitle' => 'speakers',
    'term_fields' => ['title' => 5, 'description.value' => 1],
    'related_term_fields' => ['speaker.title' => 3, 'topic.name' => 2, 'tracks.name' => 2],
    'seo' => ['title' => 'title', 'description' => ['field' => 'teaser', 'max' => 160], 'image' => 'cover', 'author' => 'speakers'],
],

Content type options ​

The key under content_types (talk) names the type in code, route names and views.

KeyTypeDefaultEffect
rolestringrequiredprimary, facet, page or reference. See Roles.
entity_typestringrequiredDrupal entity type, such as node or taxonomy_term. The resource type is entity_type--bundle.
bundlestringrequiredDrupal bundle.
sourcestringThe default SourceName of the Source that serves this type. Must be declared.
native_collectionstringThe bundlePath below the JSON:API root used for listings and search, for example track or node/article.
url_prefixstringThe type keyPublic path segment. An empty string serves the type at the site root.
alias_prefixstringThe type keyPrepended to the alias before Drupal resolves it, and removed again in public URLs. May be empty.
listing_path?stringnullPublic listing path with a leading slash. The route is named {key}.index. Without it, the type has no listing. Unique across types.
per_page?intnullItems per listing page. Required for a type that has a listing.
default_sort?stringnullUpstream sort of listings, such as -created.
fieldsmap[]Scalar values to read. See Fields.
relationsmap[]Links to other types, URLs and images. See Relations.
includesmap[]Relation names to include per context: item for the item page, listing for listings and search rows. Image relations include their file.
filtersmap[]Search filters. They apply on this type's tab only. See Filters.
sortsmap[]Name to upstream sort, offered on the search page. The first is the default. title is always offered.
searchablebooltrue for primary, else falseWhether this type has a search tab and suggestions. Never true for a page or reference; a primary with false keeps its routes and pages.
conditionslist[]Rules the type's entries must satisfy to appear in listings, filter options, search and suggestions; all must hold. Item pages are not affected.
title_attribute?stringnullName attribute used for options, suggestions and the title sort. Required for the target of an equals filter. When the title sort or relevance without a term needs a path, the order is title_attribute, then sorts.title, then the first term_fields path.
term_fieldsmaptitle attribute at weight 1Drupal path to weight. The paths a typed term is matched against with CONTAINS.
related_term_fieldsmap[]Related paths to weight. Each is searched with its own request, and a match adds its weight.
referenced_bymap[]For references: holder type key to the field that holds this type's UUID. The holder must declare that field.
optionalbooltrue for reference, else falseA bad response for an optional type is dropped and logged instead of failing the page.
seomapnullPage metadata. See SEO settings.
views.item?stringnullView for the item page. Wins over the default chain. See Views and overrides.
views.index?stringnullView for the listing page.
entity?stringEntityClass that extends Entity to use for this type.
decorator?stringnullClass implementing EntityDecorator, resolved from the container. It runs once per response with the type's entities and returns extras by entity id, read with $entity->extra($name). Nothing is cached.
routesmap[]Page type only: slug to URL with a leading slash. The route is named page.{slug}. Slugs are unique across pages.
suggest_subtitle?stringnullContent relation whose first entry's title appears beside a suggestion.

Roles ​

The role derives from entity_type: node is a primary, any other JSON:API entity type is a facet. role is written only to make a node a page or a reference; a role that contradicts the entity type fails validation. bundle is optional and defaults to entity_type.

RoleGetsRequires
primaryItem route, listing route, filters, sorts and a search tab (set searchable to false to opt out).
facetItem route and listing route when it has a path alias or sets url_prefix or listing_path; a search tab when searchable is true.
pageRoutes from its routes map only. Never searchable.
referenceNo routes. Reached through a field of another type, possibly on another Source. Never searchable.referenced_by

A type whose entity has no path alias (not a node or a term) has Entity::path equal to null and url() throws. There are no inverse relations: a primary lists the primaries related to it through the other type's equals filter on its relation.

Fields ​

A field reads one Drupal attribute under the name you choose.

KeyTypeDefaultEffect
sourcestringrequiredAttribute path on the resource. Dots reach into nested values, such as description.value.
typestringstringstring, date, html, excerpt, integer or boolean. See the table below.
requiredboolfalseA missing or empty value is a bad response for the whole page.
length?int200 for excerptExcerpt length in characters. Only for excerpt.
TypeResult in the view
string, dateA non-empty string, or null.
htmlDecoded HTML with links to Drupal and file paths rewritten. An empty string when empty.
excerptPlain text shortened to length.
integer, booleanAn int or a bool, or null.

A required field returns its raw non-empty value whatever its type. Field and relation names must not be id, type, path or url, and a name cannot be both a field and a relation.

Relations ​

KeyTypeDefaultEffect
typestringcontentcontent points at another content type and maps to Entity. image follows a media entity to an Image. file reads the file entity in via into a File (url, name, mime, size, extension(), humanSize()).
viastringrequiredDrupal relationship name. It is also the include path.
to?stringnullTarget content type key. Required for content, not allowed for image and file.
manyboolfalsetrue gives a list, false a single value or null.
optionalboolfalseA relation that fails to map is dropped and logged instead of failing the page.
image_field?stringfield_media_imageFile relationship on the media entity. Only for image relations.

A file relation takes only via, holds one file and is null without a file or a uri. An includes entry may be dotted, such as documents.file: the relation, then a relation of its target type, expanded one level. An image needs a media entity, a file and a non-empty uri, otherwise it is null.

Filters ​

Filters narrow search on the tab of the type that declares them. A key is the URL parameter, unique across all searchable types. These names are reserved and cannot be a filter key or checkbox parameter: q, sort, tab, page. While a filter is active, search shows only the tabs of the types whose filters are in use.

KeyTypeDefaultEffect
typestringrequiredequals, year_range or boolean. See the table below.
relationstringnoneequals only: the content relation to filter by. Required.
native_path?stringnullFilter path on the native collection, such as topic.id. Required for equals and for year_range (the date path).
first_yearintnoneyear_range only: earliest year offered. Required.
fieldsmapnoneboolean only: URL parameter to ['native' => path], the boolean path on the native collection, optionally with 'present' => true when the path is a field or relationship rather than a boolean: the box then selects items where it has a value (IS NOT NULL). At least one.
matchstringanyboolean only: any selects items where at least one checked field is true, all where every checked field is.
label?stringThe key as a headlineLabel of the control.
labelsmap[]boolean only: parameter to checkbox label.
Filter typeValueBehaviour
equalsUUID of a related itemChoices come from the target type, up to 200 sorted by name. The target needs title_attribute.
year_rangeInteger from first_year to the current yearMatches the year in UTC. The dropdown lists the newest year first.
booleanOne checkbox per fieldOnly a checked box filters. It selects items whose field is true, sent upstream as 1 on the native request. A field without a native path is an error that drupal:validate reports, unless the installed search backend can answer it (see the Index extension).

For a worked boolean example, see Using boolean fields as checkbox filters.

The set of filter types is closed: a new filter shape needs package code.

Conditions ​

Each entry of conditions is one rule, for example ['attribute' => 'talk_count', 'operator' => '>', 'value' => 0]. Rules are combined with AND and always combine with the visitor's filters.

KeyTypeDefaultEffect
attributestringrequiredNative field the rule reads.
operatorstringrequiredOne of =, <>, >, >=, <, <=, IN, NOT IN, IS NULL, IS NOT NULL.
valuescalar or listnullA scalar; a list for IN and NOT IN; none for IS NULL and IS NOT NULL.
filterableboolfalseSend the native rule upstream as a filter. Otherwise it is tested in PHP after the page is fetched, so a page may come back short.

SEO settings ​

Each value names a field or relation of the type. See Views and overrides for how the view receives $seo.

KeyTypeDefaultEffect
title?stringnullField or relation that gives the page title.
descriptionstring or mapnullA field name, or ['field' => ..., 'max' => 160]. The result is a plain-text excerpt.
image?stringnullField or relation for the image. Only plain strings are used.
author?stringnullField or relation for the author of the page. Only plain strings are used.

The package builds metadata when ralphjsmit/laravel-seo is installed. An Entity subclass that implements ProvidesSeo takes over completely.

What validation checks ​

The package validates the descriptor when the app boots and reports every problem at once. The rules cover:

  • Names: declared Sources, relation targets, includes and tabs must exist; built-in names are not allowed.
  • Roles: filters only on primary types, routes only on pages, referenced_by on references.
  • Uniqueness: listing paths, page slugs and filter URL parameters.
  • Search: at least one searchable type, tabs that name searchable types once each, filter keys unique across types, a native path on every equals and year_range filter, a native path on every boolean field (unless the installed backend can answer index-only booleans), an attribute on every condition, and term_fields or a title attribute for every searchable type.

Outside production a problem stops the app. In production it is logged. See Installation.
